# NPU Rust Migration Plan

*Technical Architecture & Implementation Strategy*  
*Generated: December 2024*

## Architecture Overview

The FEAGI NPU Rust migration targets a complete rewrite of the Neural Processing Unit as a standalone, high-performance system optimized for CPU (ARM/x64 with SIMD) and GPU (WGPU/Vulkan) execution. The core architecture centers around **sparse neural representations using Roaring Bitmaps**, **temporal windowing for FCL management**, and **modular injection services** for special cortical areas. The system implements a **unified FCL candidate model** where external injections (power areas, modulators) and internal synaptic propagation contribute candidates to a single Fire Candidate List, processed atomically through GPU-accelerated membrane potential updates. Key architectural components include: (1) **FCLManager** with Roaring Bitmap-based sparse neuron storage, temporal history windowing, and memory cortical support for extended windows up to 100+ timesteps, (2) **BurstEngine** with modular mixin architecture, singleton pattern, RTOS-compatible deterministic timing, and area-agnostic special area handling, (3) **FCLInjectionService** supporting unified injection timing (pre/during/post-burst), probabilistic neuron selection, and batch processing optimization, (4) **SpecialAreaHandler** for power areas (`___pwr`), modulators, and extensible area type detection, (5) **FQSampler** with differentiated sampling modes (visualization at ~30Hz, motor/OPU at burst frequency, custom area targeting), and (6) **GPU acceleration layer** using WGPU compute shaders for vectorized membrane potential updates, sparse matrix operations, and SIMD-accelerated bitmap operations on CPU fallback.

The Rust implementation leverages **ownership-based memory safety** to eliminate Python's garbage collection overhead, **zero-copy data structures** for inter-component communication, and **async/await patterns** for non-blocking I/O operations. The system supports **no-std embedded deployment** with configurable memory allocation, **cross-platform SIMD intrinsics** (AVX2/AVX-512 on x64, NEON on ARM), and **WGPU compute pipelines** for GPU-accelerated neural computation. The architecture maintains **deterministic real-time execution** suitable for 100kHz+ burst frequencies through **lock-free data structures**, **pre-allocated memory pools**, and **fixed-size circular buffers** for all temporal history management.

## Implementation Approach

The migration strategy employs **trait-based abstractions** to support multiple backend implementations (CPU-SIMD, GPU-Compute, Embedded-Scalar) through a unified interface. Core traits include `NeuronStorage` for sparse/dense neuron representations, `FCLManager` for temporal history management, `MembraneProcessor` for vectorized potential updates, and `InjectionService` for special area handling. The **Roaring Bitmap implementation** uses the `roaring` crate with custom SIMD extensions for bitmap operations, **temporal FCL management** through `heapless::pool::Pool` for embedded deployment and `std::collections::VecDeque` for standard deployment, and **GPU compute integration** via WGPU compute shaders written in WGSL for membrane potential updates, sparse matrix-vector multiplication, and bitmap union/intersection operations.

**Memory management** follows Rust's ownership model with `Arc<Mutex<T>>` for shared mutable state, `crossbeam` channels for lock-free communication between components, and **custom allocators** (bump allocators for temporary data, pool allocators for fixed-size objects). **SIMD optimization** utilizes `std::simd` (portable_simd) for cross-platform vectorization, platform-specific intrinsics (`x86` and `aarch64` features) for maximum performance, and **auto-vectorization** through iterator adapters and slice operations. **Async architecture** implements the BurstEngine as a `tokio` task with configurable schedulers (real-time, standard), **non-blocking I/O** for FQ sampler data streaming via `tokio::net` for ZMQ replacement, and **concurrent processing** with `rayon` for CPU parallelization of membrane updates across cortical areas.

**Testing strategy** includes comprehensive **property-based testing** using `proptest` for FCL operations, **benchmark-driven development** with `criterion` for performance validation, **integration testing** with Python FFI bindings for compatibility verification, and **embedded testing** on ARM platforms with real-time constraints. The build system uses **conditional compilation** (`cfg` attributes) for feature toggling (simd, gpu, std/no-std), **cross-compilation** support for ARM targets, and **automatic optimization** levels based on deployment target (embedded vs server).

## Key Challenges & Solutions

**Performance parity challenges** arise from Python's mature NumPy ecosystem optimizations requiring **custom SIMD kernels** for sparse bitmap operations, **GPU compute shader development** for complex neural operations, and **memory bandwidth optimization** through cache-aware data layouts. Solutions include **benchmarking-driven SIMD development** using compiler intrinsics, **WGPU compute pipeline optimization** with workgroup sizing for neural operations, and **data structure co-design** between CPU and GPU representations for zero-copy transfers.

**Real-time determinism challenges** stem from Rust's ownership system potentially introducing runtime costs and **async execution model** conflicting with hard real-time requirements. Solutions leverage **compile-time optimization** through const generics for fixed-size data structures, **lock-free algorithms** using atomic operations and hazard pointers, **custom async runtime** with deterministic scheduling for embedded deployment, and **memory pool allocation** to eliminate runtime allocation/deallocation overhead.

**GPU integration complexity** involves **WGPU shader development** for neural-specific operations, **CPU-GPU data synchronization** for FCL updates, and **cross-platform GPU compatibility** across different Vulkan implementations. Solutions include **compute shader libraries** for common neural operations (membrane updates, sparse matrix ops), **double-buffering strategies** for seamless CPU-GPU data exchange, **GPU memory management** with persistent buffer allocation, and **fallback mechanisms** to CPU-SIMD when GPU resources are unavailable.

**Ecosystem integration challenges** require **zero-cost abstractions** for Python interoperability, **serialization compatibility** for existing genome formats, and **deployment flexibility** across embedded and server environments. Solutions employ **PyO3 bindings** with zero-copy data sharing, **serde-based serialization** with custom deserializers for legacy formats, **feature flags** for conditional compilation (embedded/std), and **plugin architecture** for extensible special area types and sampling modes.

## Memory & CPU Optimization Strategy

**Memory footprint minimization** targets sub-100MB operation for 1M+ neuron simulations through **bit-packed neuron states** (4-bit membrane potential quantization, 2-bit refractory states), **hierarchical sparse storage** using compressed sparse row (CSR) format for synaptic connectivity with 16-bit weight quantization, and **temporal data compression** via run-length encoding for inactive timesteps in FCL history. **Cache-optimized data layouts** employ **struct-of-arrays (SoA)** organization for neuron properties enabling SIMD vectorization, **memory-mapped circular buffers** for FCL temporal windows with 64-byte cache line alignment, and **hot/cold data separation** where frequently accessed firing states reside in L1 cache while historical data uses compressed storage.

**CPU utilization optimization** leverages **branch-free algorithms** for membrane potential updates using SIMD select operations, **loop tiling** for cache-friendly memory access patterns in sparse matrix operations, and **work-stealing thread pools** for dynamic load balancing across cortical areas. **Data structure specialization** includes **bitsets for small cortical areas** (<1K neurons), **Roaring Bitmaps for medium areas** (1K-100K neurons), **compressed bitsets for large sparse areas** (>100K neurons), **ring buffers with power-of-2 sizes** for branch-free modulo operations, and **interleaved memory layouts** for simultaneous processing of multiple neuron properties. **Memory allocation patterns** utilize **object pools** for frequent allocations (membrane updates, FCL operations), **bump allocators** for burst-lifetime temporary data, **memory mapping** for large static structures (connectome matrices), and **stack allocation** for small fixed-size operations through const generics (`[T; N]` arrays), achieving **zero-allocation steady-state operation** during burst processing.

## Specific Data Structure Optimizations

**FCL temporal storage** replaces Python's list-of-dictionaries (800+ bytes per timestep) with **packed bitfield arrays** (8-64 bytes per timestep depending on neuron density), **delta-compressed timesteps** storing only firing state changes, and **adaptive compression** switching between dense and sparse representations based on firing rate. **Neuron property storage** eliminates Python object overhead (56+ bytes per neuron) through **packed structs** with 4-byte membrane potential (f32), 2-bit refractory state, 1-bit cortical area index, achieving 7 bytes per neuron vs Python's 200+ bytes. **Synaptic connectivity** transitions from Python dict-of-lists to **compressed sparse column (CSC) matrices** with 16-bit indices and quantized weights, reducing memory from ~50 bytes per synapse to ~6 bytes while maintaining SIMD-friendly memory access patterns.

**Cortical area management** replaces Python string-keyed dictionaries with **type-erased trait objects** using 8-byte pointers vs Python's 200+ byte overhead per area, **compile-time area type dispatch** through const generics eliminating runtime polymorphism, and **area-local memory pools** preventing memory fragmentation across cortical boundaries. **Injection service optimization** employs **pre-computed injection tables** with bit-packed neuron lists, **SIMD-optimized batch injection** processing 256+ neurons per instruction, and **lock-free queues** for inter-thread communication replacing Python's GIL-protected structures. These optimizations target **10x memory reduction** (from ~2GB to ~200MB for 1M neurons) and **50x CPU efficiency improvement** through elimination of Python interpreter overhead and optimized memory access patterns.

## Theoretical Performance Limits (30 FPS Processing Budget)

**CPU-bound theoretical maximum** for 33.33ms processing window reaches **50-100 million neurons** on high-end x64 systems through **AVX-512 vectorization** processing 16 neurons per instruction, **3GHz execution** enabling ~100M instructions per timeframe, and **optimized neural kernels** achieving 4-8 neurons per instruction cycle. **Memory bandwidth constraints** limit practical throughput to **20-40 million neurons** at 500GB/s system bandwidth, requiring 14 bytes per neuron per timestep (7 bytes read + 7 bytes write), consuming ~280-560MB per frame for optimal cache utilization without spilling to main memory.

**GPU-accelerated theoretical maximum** achieves **500 million to 2 billion neurons** per 33.33ms frame leveraging **20+ TFLOPS compute capacity** with 10 FLOPS per neuron (membrane decay, synaptic accumulation, threshold check), **1TB/s memory bandwidth** supporting 4.7 billion neuron transfers per frame, and **massively parallel processing** with 2048+ compute units executing neural updates simultaneously. **Practical GPU limits** settle at **100-500 million neurons** accounting for **kernel launch overhead** (~100μs), **CPU-GPU synchronization** for FCL updates, **memory allocation fragmentation**, and **thermal throttling** under sustained 30 FPS workloads.

**Real-world performance targets** for production deployment estimate **10-50 million neurons** at 30 FPS through **conservative resource utilization** (60% peak bandwidth, 70% peak compute), **robust error handling** and **deterministic timing guarantees**, **multi-cortical area load balancing** preventing single-area bottlenecks, and **thermal headroom** for sustained operation. **Scaling architecture** supports **distributed processing** across multiple GPUs for >100M neuron simulations, **hierarchical memory management** with hot neuron caching in GPU memory and cold storage in system RAM, and **adaptive quality scaling** reducing update frequency for inactive cortical areas during peak load conditions.

## STDP & Memory Formation Architecture

**Spike-Time Dependent Plasticity (STDP) implementation** leverages the **hierarchical FCL temporal windowing** to efficiently compute pre/post-synaptic timing relationships through **sliding window correlation analysis** over customizable time ranges (1-100ms for STDP, 1-1000s for memory consolidation). **LTP/LTD calculations** utilize **vectorized temporal bitmap operations** where Roaring Bitmaps enable sub-millisecond spike timing comparisons across 10+ timestep windows, **SIMD-accelerated cross-correlation** between pre-synaptic firing patterns and post-synaptic responses, and **adaptive learning rate scheduling** based on cortical area-specific plasticity rules. **Synaptic weight updates** employ **lock-free atomic operations** for concurrent STDP modifications, **quantized weight representations** (8-16 bit) with overflow protection, and **batch processing** of weight changes to minimize memory bandwidth during plasticity updates.

**Short-term memory formation** exploits **dynamic FCL window expansion** for memory-type cortical areas (hippocampus analogs) extending temporal storage from standard 20 timesteps to 1000+ timesteps, **pattern encoding via bitmap fingerprinting** where unique firing sequences generate 64-128 bit hash signatures for rapid pattern matching, and **temporal clustering algorithms** using bitmap distance metrics to identify recurring neural motifs within extended time windows. **Long-term memory consolidation** implements **neurogenesis simulation** through dynamic neuron allocation pools, **synaptic pathway strengthening** via repeated pattern reinforcement detected through bitmap intersection analysis, and **memory replay mechanisms** where stored patterns (encoded as compressed bitmap sequences) are periodically reinjected into active FCLs during low-activity periods to strengthen long-term connections.

**Memory architecture integration** combines **multi-resolution temporal storage** with compressed historical patterns (1ms granularity for STDP, 1s granularity for episodic memory), **content-addressable memory lookup** using Roaring Bitmap similarity search for pattern retrieval, **hierarchical memory consolidation** transferring frequently accessed patterns from working memory (fast bitmap operations) to long-term storage (compressed pattern databases), and **memory-guided neurogenesis** where new neurons are dynamically allocated in cortical areas showing high pattern complexity or memory load. **Performance optimizations** include **SIMD-accelerated bitmap correlation** for pattern matching, **GPU compute shaders** for parallel STDP calculations across thousands of synapses, **temporal pattern caching** in fast memory for frequently accessed sequences, and **adaptive compression algorithms** that maintain pattern fidelity while minimizing storage overhead for long-term memory systems.
